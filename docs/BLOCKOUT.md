# Болванки (blockout): JSON прогона → стены, полы, потолки, проёмы

Документ для программиста игры. Room Forge экспортирует готовую раскладку карты (`room-forge-run`,
формат — `docs/GENERATOR.md`, §6): комнаты в мировых клетках, связанные метки, двери, декор, споты.
Ядро болванок превращает этот JSON в **чистую 3D-геометрию**: непересекающиеся объёмы стен,
плиты пола и потолка, проёмы с перемычками, заглушки тупиков и боксы мебели, а также **облицовку** —
видимые из каждой комнаты участки стен с её отделкой (обои, кафель, краска; §9). Без наложений стен
друг на друга, без щелей и без «утечек» наружу.

- Ядро: `src/blockout/core.ts` — `buildBlockoutModel`, `validateBlockout`, `propHeightM`.
- Контракт (вход, опции, выход): `src/blockout/types.ts`.
- Адаптер Babylon.js (меши, материалы, коллизии): `src/blockout/babylon.ts`, описание —
  [`docs/BLOCKOUT-BABYLON.md`](BLOCKOUT-BABYLON.md).
- Части складчатого (4D) прогона: `src/blockout/subrun.ts` (подпрогоны) и `src/blockout/pieces.ts` (куски
  комнат для портального рендера, опция `ownership` — §10).

Папка `src/blockout/` самодостаточна: `core.ts` и `types.ts` ничего не импортируют из приложения
(и вообще ничего, кроме друг друга), `babylon.ts` зависит только от `@babylonjs/core`. Её можно
скопировать в проект игры как есть.

```ts
import { buildBlockoutModel, validateBlockout } from './blockout/core';
import { buildBabylonBlockout } from './blockout/babylon';

const model = buildBlockoutModel(runJson, { deadEnds: 'panel' }); // опции — частично, остальное по умолчанию
if (model.issues.length) console.warn('проблемы входа:', model.issues);
const errors = validateBlockout(model); // [] — модель чистая
const blockout = buildBabylonBlockout(scene, model, { collisions: true });
```

## 1. Система координат

- **План** (вход и `BlockoutModel`): метры, `x` вправо, `y` **вниз** (как на плане редактора), `z` — высота
  вверх. Клетка `(cx, cy)` — квадрат `[cx·cellM, (cx+1)·cellM] × [cy·cellM, (cy+1)·cellM]`, `cellM = 0.1`.
- Пол комнаты — на `z = 0`, потолок — на `z = wallHeightM`.
- **Babylon** (только в `babylon.ts`): `X = x`, `Y = z`, `Z = −y`. Вид сверху совпадает с планом, а поворот
  плана `rot°` (по часовой при y вниз) = `rotation.y = rot·π/180` (левая система Babylon).
- Все координаты модели округлены до 1e−6 м; одна и та же грань у соседних объёмов считается одной и той
  же формулой, поэтому касания точные.

## 2. Пайплайн

Главная идея: **каждая клетка плана получает ровно один класс**. Объёмы строятся из классов, поэтому
геометрия разных классов не может наложиться в принципе.

| класс | что это | откуда |
|---|---|---|
| FLOOR(inst) | пол экземпляра | клетки `cells` экземпляров |
| PORTAL(link) | проём связи в зазоре | клетки между линиями двух связанных меток |
| CARVE(inst) | проём тупика наружу | только `deadEnds: 'open'` |
| WALL | стеновая масса | обвязка, зазоры, заполненные пустоты |
| COLUMN | колонна | замкнутая дыра внутри одной комнаты |
| EMPTY | снаружи | всё остальное |

1. **Пол.** Клетки экземпляров декодируются из строк `"y:x1-x2,x3"`. Если два экземпляра претендуют на одну
   клетку — это проблема входа (`issues`), клетка остаётся за первым.
2. **Проёмы связей.** Для каждой записи `links` находятся обе метки и проверяется, что они стоят лицом к лицу:
   противоположные стороны и расстояние между линиями ровно `settings.gap`. Проём — **пересечение пролётов**
   меток вдоль стены:
   - `gap ≥ 1` — клетки зазора `[max(начA, начB), min(конA, конB))` × `gap` клеток по нормали → PORTAL;
   - `gap = 0` — клеток зазора нет: рёбра между клеткой A и клеткой B на пересечении помечаются как
     «отверстие в перегородке».
   Метки не лицом к лицу, пустое пересечение, неизвестный экземпляр/метка, проём по полу чужой комнаты —
   проблема входа, связь пропускается (обе метки становятся тупиками).
3. **Тупики.** Несвязанные метки (`len ≥ 1`) и двери (`doors`), под которыми нет ни одной метки той же
   комнаты (дверь в никуда). Для `'open'` перед ними прорезается CARVE на `outerWallCells` клеток наружу.
4. **Дыры.** Пустые клетки, не связанные 4-связной заливкой с краем расширенного bbox: если пустоту
   окружает пол одной комнаты — COLUMN (колонна, шахта, дыра в форме комнаты), иначе — WALL (двор,
   замкнутый несколькими комнатами). Только при `fillVoids`.
5. **Обвязка.** Пустые клетки в пределах `outerWallCells` по Чебышёву от пола и проёмов связей → WALL.
   Расстояние по Чебышёву даёт закрытые внешние углы (квадратная окрестность, а не крест).
6. **Щели.** Узкие пустые просветы между массой (по ряду или столбцу, не шире `max(gap, outerWallCells)`
   клеток) и пустоты, ставшие замкнутыми после обвязки, → WALL. Только при `fillVoids`.
7. **Перегородки (gap = 0).** Каждое ребро между полами разных экземпляров — перегородка толщиной
   `partitionM` по центру ребра; рёбра проёмов — перемычка. Коллинеарные рёбра сливаются в длинные
   отрезки, узлы разрешаются без пересечений (§3.4).
8. **Слияние.** Каждый класс жадно режется на прямоугольники (по рядам: максимальная ширина, затем рост
   вниз, пока ряд совпадает целиком) → `Solid.rect` / `Surface.rects` в метрах.
9. **Облицовка** — видимые из каждой комнаты грани объёмов на высоте пола, с отделкой комнаты (§9).
10. **Мебель, комнаты, статистика.**

### Высоты объёмов

| объём | план | z0 | z1 |
|---|---|---|---|
| `wall`, `column` | клетки массы | `−slabM` | `wallH + slabM` |
| плита пола (`floors`) | клетки пола и проёмов | `−slabM` | `0` |
| плита потолка (`ceilings`) | клетки пола | `wallH` | `wallH + slabM` |
| `lintel` над проёмом (gap ≥ 1, тупик `'open'`) | клетки проёма | `doorH` | `wallH + slabM` |
| `partition` (gap = 0) | полоса `partitionM` по ребру | `0` | `wallH` |
| `lintel` в перегородке (gap = 0) | полоса `partitionM` по ребру | `doorH` | `wallH` |

`wallH = wallHeightM`, `doorH = min(doorHeightM, wallHeightM)`. Стены идут сквозь уровень плит, плиты
лежат только над своими клетками — стена и плита касаются боковыми гранями. Перегородки стоят на плите
пола и упираются в плиту потолка. При `slabM = 0` стены — от 0 до `wallH`, плиты — плоскости.
Если `doorHeightM ≥ wallHeightM`, перемычек нет, а проём сверху закрыт плитой потолка (`ceilings`
с `inst: null`).

## 3. Типовые проблемы и как они решены

### 3.1. Двойные стены и z-fighting на стыке

Наивный подход «каждая комната обносит себя стеной» даёт на стыке две стены: либо наложенные (z-fighting,
двойные коллизии), либо с щелью. Здесь стены — не свойство комнаты, а **класс клеток плана**: клетка зазора
между двумя комнатами одна, и она либо стена, либо проём. Зазор генератора `gap` автоматически становится
**одной** стеной толщиной `gap · cellM` (обвязка от обеих комнат попадает в те же клетки). Совпадающих
граней разных объёмов нет — только касания.

### 3.2. Комнаты вплотную (gap = 0)

Между полами разных экземпляров нет ни одной клетки, отдать стене нечего. Поэтому на общем ребре ставится
тонкая перегородка `partitionM` (по умолчанию 8 см) — по `partitionM/2` в каждую комнату. Она стоит на
плите пола (`z = 0…wallH`) и не пересекается с плитами. Ребро проёма связи — отверстие с перемычкой.
Тупиковая панель у такой перегородки сдвигается на `partitionM/2` к комнате (на грань, а не на ось).

### 3.3. Проёмы разной длины

В режиме `match: 'tag'` метки связи могут быть разной длины и пересекаться частично. Проём — ровно
**пересечение** пролётов; хвосты более длинной метки — стена. `Opening.widthM` — ширина в свету.

### 3.4. Т- и Х-узлы перегородок, углы

Если просто нарисовать каждую перегородку на всю длину, в узле квадрат `t×t` окажется внутри двух боксов.
В каждом узле сетки (где сходятся рёбра обеих осей) решается, кто его занимает:

- **Т-узел** — прямая ось проходит насквозь, ответвление обрезано на `t/2` и упирается в её грань;
- **Х-узел** — насквозь идёт ось с бо́льшим числом сплошных перегородок (при равенстве — вертикальная),
  вторая обрезана с обеих сторон;
- **угол (L)** — одна перегородка доходит до узла, вторая обрезана и добирает свою четверть квадрата
  отдельным боксом `t/2 × t/2`; внешняя четверть угла (если там пол) тоже закрывается — комната, которая
  огибает угол, видит ровный угол перегородки, а не вырез `t/2`;
- узел с проёмами: насквозь всегда идёт сплошная ось; если прямая — две перемычки соседних проёмов, а
  ответвление сплошное, ответвление доходит до оси, перемычки обрезаны и добираются половинкой квадрата.
  Так ниже двери соседи не сообщаются через угол узла.

Узлы на внешней обвязке не нужны: перегородка стоит только над полом и упирается торцом в грань массы.

### 3.5. Углы стен

Внешние и внутренние углы обвязки закрыты автоматически: обвязка — квадратная окрестность пола
(расстояние Чебышёва), диагональная клетка угла тоже стена. Внутренний угол Г-образной комнаты — просто
клетки массы, без стыков боксов.

### 3.6. Перемычки

Над каждым проёмом связи (и над прорезанным тупиком `'open'`) — `lintel` от `doorHeightM` до верха плиты
потолка: проём не дырявит потолок, а комнаты не видят друг друга поверх двери. При gap = 0 перемычка —
продолжение перегородки (`doorH…wallH`), над ней общая плита потолка комнат.

### 3.7. Тупики и двери в никуда

Генератор оставляет метки без пары (`openConnectors`), а в комнате могут быть нарисованные двери, под
которыми нет связи. Варианты (`deadEnds`):

- `'wall'` — глухая стена;
- `'panel'` (по умолчанию) — стена + `DeadEnd`: линия по грани стены со стороны комнаты, нормаль внутрь,
  ширина и высота двери; адаптер рисует по ней «заколоченную» дверную панель. Дверь, лежащая на любой
  метке своей комнаты, отдельно не дублируется; `DeadEnd.source` — `'connector'` или `'door'`;
- `'open'` — проём прорезан наружу сквозь обвязку (с полом и перемычкой), `DeadEnd` нет. Для предпросмотра
  одной комнаты; прорезка не идёт вплотную к полу чужой комнаты и к проёмам связей.

### 3.8. Дыры и колонны

Комнаты бывают с отверстиями (колонны техподполья, шахты). Замкнутая пустота внутри **одной** комнаты
целиком заполняется `column` на всю высоту; пустота, окружённая несколькими комнатами (двор), — `wall`.
С `fillVoids: false` дыра получает обычную обвязку, середина остаётся пустой (снаружи не видна).

### 3.9. Щели между стенами

Если две комнаты стоят дальше `gap`, между их обвязками остаются узкие просветы, а кольцо комнат может
замкнуть пустоту, до этого связанную с улицей. Просветы шириной ≤ `max(gap, outerWallCells)` клеток и
замкнутые пустоты заливаются массой (`fillVoids`). Это убирает лишние грани и щели, в которые проваливается
камера или физика.

### 3.10. Общие плиты пола и потолка

Плиты — по комнатам (`Surface.inst` — экземпляр, удобно для подсветки и выбора) плюс одна поверхность
`inst: null` для всех проёмов. Плиты разных комнат и проёмов касаются гранями и вместе дают сплошной пол
без зазоров; потолок над проёмом — перемычка.

### 3.11. Утечки наружу

Каждая клетка пола окружена либо полом/проёмом, либо массой (обвязка ≥ 1 клетки), либо перегородкой
(gap = 0). `validateBlockout` проверяет это независимо, по готовой геометрии (§6).

### 3.12. Производительность и число мешей

Сетка плана — типизированные массивы, все шаги линейные. Жадное слияние даёт порядка **5 стеновых боксов
на комнату**. На фикстурах реальных прогонов (`src/blockout/fixtures/`):

| прогон | комнат | solids (wall / column / lintel / partition) | прямоуг. пола | openings | deadEnds | время |
|---|---|---|---|---|---|---|
| `run-gap0-30` | 33 | 209 (121 / 0 / 32 / 56) | 47 | 32 | 27 | ≈ 10–25 мс |
| `run-gap1-30` | 31 | 195 (163 / 2 / 30 / 0) | 78 | 30 | 26 | ≈ 7–20 мс |
| `run-gap1-150` | 150 | 861 (706 / 5 / 150 / 0) | 378 | 150 | 141 | ≈ 35–60 мс (первый вызов ≈ 130 мс, JIT) |
| `run-gap3-20` | 20 | 128 (107 / 2 / 19 / 0) | 53 | 19 | 16 | ≈ 4–8 мс |

Babylon-адаптер по умолчанию сливает объёмы одного вида в один меш (`merge`, внутри — подмеши по тайлам
16×16 м для отсечения камерой), так что стены дают единицы–десятки draw calls. Полы и потолки идут мешем
на комнату, мебель — мешем на предмет (плюс плоскость текстуры): на 150 комнатах это ≈ 1000 мешей и
≈ 880 draw calls при облёте всей карты, ≈ 100 — от первого лица. Как сократить мебель — см.
[BLOCKOUT-BABYLON.md](BLOCKOUT-BABYLON.md).

### 3.13. Поворот и система координат

Вход уже в мировых клетках (поворот экземпляров применён генератором), модель — в метрах плана. Поворот
нужен только мебели: `PropBox.rot` — градусы по часовой на плане (как во входе), `w` — по x и `d` — по y
при `rot = 0`. Переход в Babylon — §1.

## 4. Опции (`BlockoutOptions`, по умолчанию `DEFAULT_BLOCKOUT`)

| поле | по умолчанию | смысл |
|---|---|---|
| `wallHeightM` | 2.5 | от пола до потолка, м (хрущёвка ≈ 2.5) |
| `doorHeightM` | 2.1 | высота проёма, м (блоки ДГ 21-х); ≥ `wallHeightM` — без перемычек |
| `outerWallCells` | 2 | толщина обвязки в клетках (≥ 1); внутренние стены = зазор генератора |
| `partitionM` | 0.08 | толщина перегородки при gap = 0, м (не толще 0.9 клетки) |
| `slabM` | 0.2 | толщина плит пола/потолка, м (0 — плоскости) |
| `ceilings` | true | строить потолки |
| `props` | true | боксы мебели |
| `spotProps` | true | ставить и выпавшее на спотах (`content.kind = 'prop'`) |
| `deadEnds` | `'panel'` | `'wall'` / `'panel'` / `'open'` (§3.7) |
| `fillVoids` | true | заливать дыры, дворы и щели (§3.8–3.9) |
| `cutEnds` | — | тупики меток со срезанной связью (`RunConnector.cut`, подпрогон); нет — как `deadEnds` |
| `ownership` | — (выкл.) | владение: у каждого объёма и половины проёма — комната-владелец (§10) |

Опции нормализуются (недопустимые значения → по умолчанию или ближайшие допустимые; обвязка < 1 клетки и
перегородка толще клетки — с записью в `issues`); в `model.options` лежат фактически использованные.

## 5. Формат `BlockoutModel`

| поле | тип | что это |
|---|---|---|
| `format`, `version`, `units`, `axes` | — | `'room-forge-blockout'`, `1`, `'m'`, `'plan: x right, y down, z up'` |
| `cellM` | number | размер клетки, м |
| `options` | `BlockoutOptions` | фактически использованные опции |
| `bounds` | `Rect` | габарит всей геометрии на плане, м |
| `solids` | `Solid[]` | твёрдые объёмы `{ kind, rect, z0, z1 }`, попарно не пересекаются (касание гранями допустимо); при `ownership` — ещё `inst` (владелец) |
| `floors` | `Surface[]` | `{ inst, rects, finish, z: 0 }` — пол по комнатам (`finish` — отделка пола); `inst: null` — пол всех проёмов (`finish: null`), при `ownership` — по половинам, `owner` — чья половина |
| `ceilings` | `Surface[]` | `{ inst, rects, finish: null, z: wallH }` — нижняя грань потолка; плита — вверх на `slabM` |
| `openings` | `Opening[]` | связанные проёмы: `a`, `b` (метки), `rect` (на всю толщину стены; при gap = 0 — толщина перегородки), `axis` (`'x'` — проходят вдоль x), `widthM` (в свету), `heightM` |
| `deadEnds` | `DeadEnd[]` | только `'panel'`: `inst`, `connector` (id метки или двери), `line` по грани стены, `normal` внутрь комнаты, `widthM`, `heightM`, `source` |
| `faces` | `WallFace[]` | облицовка стен по комнатам (§9): `inst`, `line`, `normal`, `z0`, `z1`, `part`, `finish` |
| `finishes` | `RunFinish[]` | таблица отделок — копия `RunExport.finishes` как есть (с `tex`); пусто, если в прогоне её нет |
| `props` | `PropBox[]` | мебель: `inst`, `source` (`'decor'`/`'spot'`), `propId`, `name`, центр `x, y` (м), `rot`, `w`, `d`, `h` (м), `color`, `tags` |
| `rooms` | `RoomInfo3D[]` | `inst`, `roomId`, `name`, `tags`, `bbox`, `anchor` (центр наибольшего прямоугольника пола — подпись/спавн камеры), `tier`, `floorAreaM2`, `finish: { wall, floor }` |
| `stats` | — | `floorCells`, `wallCells` (масса + колонны), `solids`, `openings`, `deadEnds`, `ms` |
| `issues` | `string[]` | проблемы входа по-русски (что не так и что сделано) |

Виды `Solid.kind`: `wall` — масса (обвязка, стены между комнатами, заполненные пустоты), `partition` —
тонкая перегородка, `lintel` — перемычка, `column` — колонна в дыре одной комнаты.

Высота мебели — `propHeightM(tags, name)`: таблица по тегам и словам имени (стенка 2.0, шкаф 1.9,
сервант/стеллаж 1.8, холодильник 1.5, плита/мойка/тумба 0.85, стол 0.75, стул/табурет 0.45, кровать 0.5,
диван 0.85, ванна 0.6, унитаз 0.75, ковёр 0.01, батарея 0.6, лифт 2.2, по умолчанию 0.8). Мебель в
проверке пересечений не участвует (она стоит на полу и может касаться стен, как нарисована).

## 6. Проверка модели: `validateBlockout(model)`

Независимая объёмная проверка готовой модели — классификации клеток она не доверяет, работает только по
боксам. Возвращает список проблем по-русски, `[]` — всё чисто.

1. **Пересечения**: все `solids` плюс плиты пола и потолка как объёмы попарно, допуск 1e−6 м (касание
   гранями — не пересечение). Пары ищутся через сетку корзин на плане, а не O(n²).
2. **Утечки**: каждый край каждого прямоугольника пола (с шагом в клетку) — снаружи либо пол той же
   комнаты, либо пол проёма, либо масса/перегородка на всю высоту комнаты. Если снаружи пол другой
   комнаты (gap = 0) — на ребре обязана стоять перегородка или быть связанный проём. В режиме
   `deadEnds: 'open'` открытый наружу торец прорезанного тупика утечкой не считается.
3. **Проёмы**: ниже высоты двери в прямоугольнике проёма нет ни одного твёрдого объёма.
4. **Облицовка**: каждая грань лежит в плоскости грани твёрдого объёма с нужной стороны (по всей длине
   и высоте покрыта объёмами, чья грань совпадает с её линией); стеновая облицовка не стоит поперёк
   проёма ниже двери; облицовки одной комнаты на одной линии не накладываются; каждый закрытый край пола
   облицован (на грани массы или перегородки, не дальше `t/2` внутрь); суммарная длина стеновой облицовки
   комнаты равна закрытой части периметра её пола (периметр минус проёмы и прорези `'open'`) — точно, а у
   граней перегородок (смещены с сетки клеток на `t/2`) — с допуском `partitionM` на грань.
5. При `slabM = 0` (плиты — плоскости) — стена/колонна на полу по плану.

Точка края пола, попавшая ровно на стык двух объёмов, считается закрытой (при владении масса режется и
по полуклеткам — стык приходится на середину клетки, где лежат точки проверки); перегородку ищут по обе
стороны ребра (при владении она поделена по ребру). В режиме `'open'` (`deadEnds` или `cutEnds`) открытым
краем может быть пол проёма и ребро проёма без пола за ним — так выглядит кусок комнаты без соседа (§10).

Удобно звать после загрузки уровня в debug-сборке, а также после ручных правок модели.

## 9. Облицовка и отделка

### 9.1. Зачем отдельный слой

Объёмы (`solids`) — это «бетон»: слитые боксы, у которых одна грань может смотреть в несколько комнат
(стена между комнатами при gap ≥ 1 — один бокс: левая грань в комнате A, правая — в B), а грани
перегородок начинаются и кончаются в узлах. Клеить обои «по комнатам» на такие боксы нельзя: у бокса нет
комнаты, у грани — понятных границ. **Облицовка** (`model.faces`) — отдельный тонкий слой: для каждой
комнаты — прямоугольные участки стен, которые видны из неё, с отделкой этой комнаты. Объёмы она не меняет
(коллизии и проверка пересечений — по-прежнему по `solids`); адаптер рисует её плоскостью на 1–2 мм перед
гранью, поэтому мерцания с гранью бокса нет. Облицовка строится всегда, и без отделки (`finish: null`) —
тогда её можно красить цветом или сеткой.

### 9.2. Как строится

- Каждая клетка пола делится на 3×3 под-клетки по линиям `x`, `x + t/2`, `x + 1 − t/2` (и так же по `y`):
  угловые — четверти квадратов узлов перегородок, боковые — полосы перегородок вдоль рёбер, центр — пол.
  Это та же сетка, по которой нарезаны перегородки, поэтому каждое ребро «свободная под-клетка комнаты |
  твёрдая под-клетка» — точно кусок грани объёма.
- Твёрдое на всю высоту (масса, колонна, перегородка) → `part: 'wall'`, `z = 0…wallH`. Перемычка (проём
  связи, отверстие в перегородке gap = 0, прорезь `'open'`) → `part: 'lintel'`, `z = doorH…wallH`; с каждой
  стороны проёма — свой кусок своей комнаты. Если дверь не ниже потолка — перемычек и их облицовки нет.
- Куски сливаются по прямой, пока это одна комната, одна линия и одна часть: облицовка рвётся на углах, на
  проёмах и на переходе «масса → перегородка».
- При gap ≥ 1 облицовка идёт ровно по краю пола. При gap = 0 — по грани перегородки, в `t/2` от ребра, с обеих
  сторон. Где перегородка упирается в массу, грань стены уступом отходит на `t/2` — торец перегородки тоже
  облицован. В Т/Х-узлах облицовка обрывается на грани сквозной перегородки (каждая комната видит свой
  прямоугольник), угол L ровный.
- Колонны облицованы со стороны комнаты. Тупики `'wall'`/`'panel'` — облицовка идёт по стене как обычно
  (панель адаптер рисует поверх); `'open'` — проём без облицовки стены, над ним облицованная перемычка.
- Не облицовываются откосы проёмов (боковые грани в толще стены — ничьи) и нижняя грань перемычки. Исключение
  при gap = 0: перемычка центрована по ребру, и там, где проём кончается у массы, её торец выступает на `t/2`
  из плоскости стены — он виден из комнаты и облицован (короткий кусок `part: 'lintel'` длиной `t/2`).
- Стоимость: ≈ 6 мс на 150 комнатах (≈ 10–15 % от построения модели). На фикстурах: `run-gap0-30` — 398
  граней (76 над проёмами), `run-gap1-30` — 264 (60), `run-gap1-150` — 1300 (300), `run-gap3-20` — 177 (38).

### 9.3. Формат

`WallFace`:

| поле | что это |
|---|---|
| `inst` | комната (экземпляр) |
| `line` | `[x1, y1, x2, y2]` — линия грани на плане, м. Если смотреть на стену **из комнаты**, линия идёт **слева направо** (нормаль `+x` → линия к `−y`, `−x` → к `+y`, `+y` → к `+x`, `−y` → к `−x`) |
| `normal` | единичная нормаль по оси плана, внутрь комнаты |
| `z0`, `z1` | `0…wallH` у `'wall'`, `doorH…wallH` у `'lintel'` |
| `part` | `'wall'` — стена на всю высоту, `'lintel'` — участок над проёмом |
| `finish` | id отделки стен комнаты (`model.finishes`) или `null` |

Отделка приходит из прогона: таблица `RunExport.finishes` (`RunFinish`: `id`, `name`, `surface`
(`'wall'`/`'floor'`), средний `color`, бесшовная текстура `tex` (data:URI, есть при экспорте с текстурами) и
`hasTex`, размер одного повтора `tileW × tileH` в метрах, `dado`) и у экземпляров `finish: { wall, floor }`.
В модели: `faces[].finish` — отделка стен комнаты, `floors[].finish` — отделка пола (у пола проёмов и у
потолков — `null`), `rooms[].finish` — обе, `model.finishes` — копия таблицы как есть. Ссылка на
несуществующую отделку — `issues` и `null`.

### 9.4. Как движку клеить текстуры

- **Стены**: UV в метрах. `u = s / tileW`, где `s` — мировая координата вдоль линии грани в её направлении
  («вправо» для смотрящего из комнаты: для нормали `+y` это `x`, для `−y` — `−x`, для `+x` — `−y`, для
  `−x` — `y`); `v = z / tileH` (низ картинки — у пола). С мировой координатой узор идёт непрерывно по
  соседним граням одной плоскости — по обе стороны двери и через перемычку — и не зеркалится. На углах фаза
  обрывается, как у настоящих обоев. Текстура — `REPEAT` по обеим осям.
- **Dado** (двухтонная стена: кафель в санузле, масляная краска в подъезде): `dado: { finishId, heightM }` —
  от пола до `heightM` рисуется отделка `finishId`, выше — основная. Проще всего резать грань по высоте на
  два квада (`z0…h` и `h…z1`); перемычки (`z ≥ doorH`) обычно целиком выше панели.
- **Полы**: `u = x / tileW`, `v = −y / tileH` по мировым метрам — швы между прямоугольниками одной комнаты не
  видны.
- **Смещение**: облицовку ставить на 1–2 мм внутрь по `normal` (и/или depth bias), без коллизий — игрок
  упирается в стену под ней. На выпуклых углах (колонны, торцы перегородок) квады можно продлить на те же
  1–2 мм с концов, чтобы облицовки смыкались без щели.
- Готовая реализация для Babylon (меш на отделку, dado, материалы) — [BLOCKOUT-BABYLON.md](BLOCKOUT-BABYLON.md), §5.

## 10. Владение (`ownership`) и куски комнат

Нужно портальному рендеру складчатого (4D) прогона ([BLOCKOUT-BABYLON.md](BLOCKOUT-BABYLON.md), §12): там
каждая комната рисуется отдельно — текущая обычно, остальные только сквозь проёмы, — и комнаты разных слоёв
W стоят в одном месте 3D. Болванка нужна **по комнатам**: кусок комнаты не зависит от того, откуда на неё
смотрят (строится и кэшируется один раз), комната и любой её сосед стыкуются без щелей и наложений, а
комнаты, пересекающиеся в 3D, друг от друга не зависят.

### 10.1. Опция ядра

`buildBlockoutModel(run, { ownership: true })` строит ту же модель, но у каждого объёма есть владелец
`Solid.inst`, а пол (и потолок без перемычек) проёмов разбит на половины с `Surface.owner`:

- **Стеновая масса и колонны** — ближайшему полу. Сетка владения — полуклетки (сетка ×2; при gap = 0 —
  четверти клетки), расстояние до пола экземпляра — фасочное (2 за шаг по стороне, 3 по диагонали), при
  равенстве — экземпляр раньше в списке. Расстояние считается по клеткам экземпляров из входа, а не по
  классам клеток, поэтому граница «A | B» зависит только от A и B — в моделях с разным составом комнат она
  одна и та же. Стена толщиной `gap` клеток между комнатами — это `2·gap` полуклеток: делится **ровно
  пополам**, ничьих нет; первая полуклетка вокруг пола (и по стороне, и в углу) всегда своя — у каждой
  комнаты замкнутая собственная оболочка толщиной ≥ полклетки.
- **Проём связи** (пол, перемычка, откосы) — тоже по середине толщины стены: половина со стороны A — A,
  со стороны B — B. Плоскость посередине — это и граница кусков, и плоскость портала, и место, где меняется
  текущая комната.
- **Перегородка gap = 0** — по ребру: половина толщины каждой стороне; четверти квадратов узлов — комнате
  клетки под ними.
- Пол, потолок, облицовка, мебель, тупики — как и были, по комнатам (`inst`).

Если два экземпляра пересекаются (во входе это проблема — в части складчатого прогона соседи комнаты
между собой пересекаться могут) и клетка пола за проёмом связи досталась третьей комнате, при владении
она отдаётся комнате связи — проём не пропадает.

Без опции модель та же, что раньше (полей `inst`/`owner` нет).

### 10.2. Кусок комнаты (`src/blockout/pieces.ts`)

```ts
import { buildPiece, piecePortals, pieceFloorRects, mergePieces } from './blockout/pieces';

const piece = buildPiece(run, 'i12', { deadEnds: 'panel' }); // модель «i12 + соседи» с владением → только своё
const portals = piecePortals(run, piece, 'i12');             // проёмы: плоскость (at), ось, направление, ширина, высота
const floor = pieceFloorRects(piece, 'i12');                 // пол + свои половины проёмов — «где стоит игрок»
```

- `neighborhoodModel(run, id)` — модель подпрогона «комната + все соседи по связям» с владением; связи
  соседей наружу — стены (`cutEnds: 'wall'`). `pieceOf(model, id)` — из неё только своё: объёмы с
  `inst = id`, пол/потолок (свои и свои половины проёмов), облицовка, тупики, мебель, комната, проёмы к
  соседям. `buildPiece` = одно за другим.
- Соседи комнаты между собой могут пересекаться (localRadius 1) — на кусок это не влияет: ему нужны только
  границы «комната | сосед».
- Кусок замкнут: каждый край пола закрыт своей полустеной, кроме своих половин проёмов. Проверка куска и
  стыковки — `validateBlockout(mergePieces([A, B]))`: склейка кусков с режимом `cutEnds: 'open'` (проёмы к
  комнатам вне склейки — открытые половины, у них проверяется только своя половина).
- `openCut` (последний аргумент `buildPiece`/`neighborhoodModel`) — метки самой комнаты с флагом `cut`
  становятся проёмом в темноту (`'open'`), у соседей флаг снимается: так рисуются ещё не раскрытые двери
  бесконечного мира (`docs/GENERATOR-4D.md` §15).

Стоимость: кусок — модель из 3–7 комнат, ≈ 3–8 мс (на 70 комнатах все куски — ≈ 0.3–0.6 с в node);
сетка владения — Дейкстра с корзинами на сетке ×2, линейна.

Ограничение gap = 0: во внутреннем углу, где полы трёх комнат сходятся к одной клетке массы, облицовка
комнаты может на ≤ 2.5 см не иметь объёма своего куска за собой (видно только без отделки); объёмы соседей
не пересекаются, проёмы сквозные. Для складчатых прогонов рекомендуется gap ≥ 1.
