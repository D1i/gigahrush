# Кооп «Прогулки»: лобби по UUID, через Steam

До 4 игроков в одном бесконечном мире «Прогулки» (вкладка «3D»): видят друг друга, проходят сквозь друг друга
(рядом — медленнее), двери, открытые кем-то одним, открываются у всех. Главный путь — **Steam** (§4): один из игроков
запускает сервер, остальные подключаются прямым туннелем через сеть Steam (Spacewar, AppID 480); без Steam — свой
сервер по адресу.

| что | где |
|---|---|
| relay-сервер лобби (без зависимостей, свой WebSocket) | `tools/coop-server.mjs` (тесты — `tools/coop-server.test.mjs`) |
| мост Steam: сервер у хоста, туннель P2P Steam у игроков | `tools/steam-bridge.mjs` (`npm run steam`; тест туннеля — `tools/steam-bridge.test.mjs`) |
| протокол (сообщения, UUID, хэш проекта, адрес сервера) | `src/coop/protocol.ts` |
| клиент лобби: соединение, копия мира, журнал операций, чекпойнты | `src/coop/session.ts` (тест на настоящем relay — `session.test.ts`) |
| аватары, своё положение, «рядом — медленнее» | `src/coop/presence.ts` |
| лобби страницы, профиль игрока | `src/coop/store.ts` |
| раздел «Онлайн», модалка лобби, HUD | `src/coop/CoopPanel.tsx`, `coop.css` |
| операции мира (`WorldOp`), `WalkSession.request / apply` | `src/view3d/walk.ts` |
| аватары в портальном рендере (`PortalRenderer.extras`) | `src/view3d/portal.ts` |
| QA в браузере (два игрока) | `node tools/qa-coop.mjs` → `tools/qa/coop-*.png`; через мост Steam (без Steam) — `node tools/qa-coop-steam.mjs` |

## 1. Как играть

Через Steam — §4.1. Без Steam:

1. Запустить игру с сервером:
   - разработка — `npm run dev` (relay сам висит на том же сервере, путь `/coop`); по локальной сети —
     `npm run dev -- --host`, друзья открывают `http://<ваш IP>:5173/`;
   - сборка — `npm run build`, затем `npm run coop-server` (порт 8787, `--port N` — другой): на `http://<ваш IP>:8787/`
     и игра, и relay. Игра, открытая из файла (`dist/index.html`), подключается к `ws://localhost:8787/coop` или к
     адресу, указанному в модалке.
2. Вкладка **«3D»** → слева раздел **«Онлайн»** → **«Подключить онлайн»** → модалка лобби:
   - **«Создать лобби»** — новый UUID; мир лобби — текущие настройки «Прогулки» (сид, квартиры, биом старта) и ваш
     проект (комнаты, отделка). Код лобби — в модалке, кнопка «Копировать»;
   - **«Подключиться по UUID»** — вставить код друга.
   Там же — имя, цвет игрока и адрес сервера (пусто — тот, с которого открыта игра).
3. Источник переключается на «Прогулку» лобби; новичок появляется рядом с другим игроком (после перезагрузки
   вкладки — на своём месте: вкладка помнит лобби и входит снова сама).
4. **«Выйти»** — назад в свою одиночную прогулку (она не менялась: мир лобби отдельный, в localStorage не пишется).

Правила для игрока:

- **Видите друг друга** — капсула цвета игрока, «визор» смотрит туда же, куда игрок, над головой — имя. Видно
  ровно там, где видна комната игрока: сквозь проёмы, но не сквозь стены и не из комнат другого слоя W, стоящих в
  том же месте 3D.
- **Сквозь друг друга можно пройти, но рядом (ближе 0.75 м) оба идут на 75% медленнее** — в HUD «рядом игрок —
  шаг медленнее». Толкаться нельзя, «застрять» друг в друге — тоже.
- **Двери общие**: открыл кто-то один — открывается у всех (у тех, кто видит дверь, — с той же анимацией), за ней
  у всех одна и та же квартира. Нажали одну дверь вдвоём — обоим она и откроется.
- Лестница вниз, выходы лифта, обвалы снега — тоже общие: кто бы ни прошёл первым, дальше у всех один мир.
- **Поза видна**: напарник на четвереньках (C или снежный лаз) — аватар лежит, скрючившись — ниже ростом.
- **Засыпало обвалом — напарник откапывает**: подойти ближе 1.6 м → «E — откапывать: имя»; каждое нажатие — шаг
  откопки засыпанного (`digMate` нажатий против `digSelf` своих), у него вспышка «имя откапывает».
- Сцены спец-локаций (лифт, лестница, ангар) — у каждого своя: напарник внутри лифта не виден, пока не вышел; ушёл со
  вкладки «3D» — тоже не виден, пока не вернулся.

## 2. Как устроено

### 2.1. Один мир у всех — журнал операций

Мир «Прогулки» генерируется детерминированно по сиду и **истории** раскрытий (`StreamWorld`: тот же мир + та же
операция → тот же мир; сохранение восстанавливает мир так, что дальше он растёт «ровно так же»). Поэтому у каждого
игрока — своя копия мира (`WalkSession`), а меняется она только **операциями мира** (`WorldOp`, `walk.ts`):

| операция | что делает | кто зовёт |
|---|---|---|
| `enter {id}` | счётчик переходов + раскрыть окрестность (`ensureAround`, `ensureVisible` — **синхронно**) | шаг в комнату (`FoldDriver.onEnter`) |
| `door {inst, conn}` | открыть закрытый выход квартиры → комната за ним (уже открыта — та же комната) | E у двери |
| `descend {id}` | спуск из спец-локации → комната ниже | выход лестницы / ангара |
| `ascend {id, floor, side}` | выход лифта → комната выше/ниже | выход лифта |
| `collapse {inst, conn}` | обвал снежного хода | снежные ходы |
| `lamp {inst, spot}` | керосиновую лампу взяли со спота (у всех спот пуст; кто первый — того и лампа) | E у лампы (общага) |
| `dig {inst, conn, amount}` | раскопка завала: работа копится от всех игроков, набралось 1 — проём снова открыт | снежные ходы |

`WalkSession.request(op)` — в одиночной игре применяет сразу; в коопе (`sink`) отправляет на сервер. Сервер
нумерует операции (`seq`) и рассылает **всем, включая автора**; каждый применяет их `apply(op)` строго по порядку
`seq`. Своя операция тоже применяется только когда вернулась — результат `request` (id комнаты за дверью и т. п.)
приходит с ней. Задержка — один круг до сервера; дверь всё равно сначала отпирается (анимация), мир растёт за
закрытым полотном.

**Правило для кода**: мутации мира из view-кода — только `session.request({ k: … })`. Новая мутация = новый вид
`WorldOp` + `case` в `WalkSession.apply`. Чтение (`locationOf`, `doorState`, `clusterAt`…) — напрямую.

### 2.2. Проект

Мир строится по проекту (комнаты, веса, биомы). У лобби — проект создателя (JSON) и его хэш (`hashText`). Входящий
сравнивает хэш своего проекта: совпал — берёт свой, нет — скачивает проект лобби (≈1.5 МБ с текстурами). Свой
проект в редакторе не меняется: проект лобби живёт только в копии мира.

### 2.3. Сервер: лобби, чекпойнты, переподключение

- Лобби — по UUID, в памяти сервера; без игроков живёт 30 мин. В `npm run dev` хаб один на процесс — перезапуск
  dev-сервера лобби не теряет.
- **Хост** — первый из подключённых (★ в списке). Раз в 20 с (и при выходе) он шлёт **чекпойнт** — `world.save()` на
  последнем `seq` + открытые двери; журнал до него сервер забывает. Новичок получает чекпойнт + хвост журнала.
  Ушёл хост — хостом становится следующий.
- **Сверка копий**: с чекпойнтом приходит отпечаток мира (`WalkSession.fingerprint`); не совпал со своим на том же
  `seq` — копия разошлась: пересборка из чекпойнта (не должно случаться; счётчик `CoopSession.diverged`).
- **Обрыв**: клиент переподключается сам (0.5 → 10 с), с `since` = последний применённый `seq` — получает только
  пропущенное; операции, отправленные без связи, уходят после. Журнал уже обрезан чекпойнтом — копия собирается
  заново (сцена пересоздаётся).

### 2.4. Положение и аватары

- Своё положение (комната + камера + поворот + «в спец-локации») — ~15 раз в секунду по таймеру (не по кадрам сцены:
  в спец-локации рисуется её сцена, а другим надо узнать «он в локации»), только когда изменилось (иначе раз в
  секунду); ушёл со вкладки — `loc: 'away'`. Сервер помнит последнее — новичок сразу видит всех и встаёт рядом.
- С положением — высота глаз (`eye`, поза `src/view3d/posture.ts`: стоя 1.6, скрючившись 1.1, на четвереньках ~0.5;
  нет поля — 1.6) и флаги: `buried` (засыпан обвалом), `lamp` (держит горящий фонарь — биом «Общага»), `dead` (погиб —
  аватар не показывается). Аватар ниже 0.8 м глаз — лежит вдоль взгляда, выше — капсула сжата по росту.
- Аватар движется плавно (экспонента), скачок дальше 3 м (шов хода, лифт, телепорт) — сразу.
- Портальный рендер рисует аватар **вместе с его комнатой** (`PortalRenderer.extras`): в её области стенсила, с её
  отсечением и сдвигом. Аватар ближе 0.8 м к проёму рисуется и с соседом за ним — тело, вышедшее за плоскость
  проёма, не обрезается. Режим «Набор (PVS)» — обычные меши, пока комната аватара в наборе; облёт — не видны.
- Замедление: после ввода и коллизий камеры (`onAfterCheckInputsObservable`) сдвиг за кадр урезается до 0.25
  (`SLOW_FACTOR`), если другой игрок ближе `SLOW_RADIUS_M` = 0.75 м по горизонтали (и 1.2 м по высоте) в той же
  комнате или у общего проёма. Каждый замедляет себя сам — значит, замедлены оба. Телепорты (> 0.5 м за кадр) не
  трогаются.

### 2.5. Действия и события без журнала

- **`act`** — действие игрока над другим игроком, только адресату: `dig` — откапывать засыпанного (у него —
  `SnowWalk.mateDig`). `CoopSession.act(to, a)` / `onAct`.
- **`fx`** — временное событие всем остальным в лобби, без номера и журнала: мигание и темнота, состояние руки,
  двери, что закрываются сами (биом «Общага»). Опоздавшим не досылается — шлющий (обычно хост) повторяет состояние
  сам. `k` — вид (≤ 16 символов), `d` — JSON ≤ 2 КБ (больше — сервер отбрасывает). `CoopSession.fx(k, d)` / `onFx`.
  Всё, что меняет мир навсегда, — не сюда, а в `WorldOp` (§2.1).
  Общага: `obsh` — срез режиссёра от хоста ~10/с, `obshSee` — клиент видит руку / смотрит на двери, `obshDoor` — клиент
  открыл дверь комнаты (docs/LOCATIONS.md §14.3).

## 3. Протокол (JSON по WebSocket, путь `/coop`)

Клиент → сервер: `hello {v, lobby, player{id,name,color}, create?{meta, project, projectHash}, since?}`,
`op {req, op}`, `state {s}`, `act {to, a}`, `fx {k, d}`, `checkpoint {seq, save, opened, fp}` (только хост), `project`,
`bye`.

Сервер → клиент: `welcome {you, host, meta, projectHash, seq, resumed, checkpoint, ops, players}`,
`op {seq, from, req, op}`, `state {id, s}`, `act {from, a}`, `fx {from, k, d}`, `join {player}`, `leave {id}`,
`host {id}`, `sync {seq, fp}`,
`project {json}`, `error {code, text}` (`no-lobby`, `exists`, `version`, `bad`, `replaced`, `full` — 4 игрока уже в лобби; все — без переподключения).

Версия протокола — `COOP_PROTO` (клиент и сервер должны совпадать). id игрока — на вкладку (`sessionStorage`):
две вкладки одного браузера — два игрока.

## 4. Steam

### 4.1. Как играть через Steam

Нужно: Steam запущен, вход в аккаунт (у каждого игрока — свой аккаунт), игра у каждого (`npm run dev` или собранная
`npm run build`), один раз `npm install` (ставит `steamworks.js` — привязки Steamworks SDK).

1. **Сервер** (хост, кто угодно из игроков): `npm run steam -- host` — мост поднимает сервер лобби у себя и лобби
   Steam на 4 места; печатает его id. `--friends` — лобби Steam только для друзей; `--port N` — не 8787.
2. Хост в игре: «3D» → «Подключить онлайн» → блок **Steam** («Вы — сервер») → **«Создать лобби через Steam»**. Код
   игрового лобби уходит игрокам сам — через данные лобби Steam.
3. **Игрок**: `npm run steam -- join <id лобби Steam>` — или `npm run steam -- join` и в Steam: список друзей → хост →
   «Присоединиться к игре». В игре: «Подключить онлайн» → блок Steam → **«Подключиться через Steam»**.
4. Пятому — «Лобби заполнено». Хост вышел — у игроков «связь потеряна»; сервер — у хоста, без него лобби нет.

### 4.2. Как устроено

- Игра в браузере не может говорить со Steam — рядом с ней мост (Node + `steamworks.js`, AppID 480 — Spacewar,
  тестовое приложение Valve; в Steam у игроков будет «Играет в Spacewar»). Своё приложение в Steam — сменить
  `STEAM_APP_ID`.
- **Хост**: хаб лобби (тот же `createCoopHub`, `maxPlayers` 4) + лобби Steam (`createLobby`, Public / FriendsOnly, 4
  места; данные: `rf` = 1, `rf_ver` — протокол, `rf_host` — имя, `rf_lobby` — код игрового лобби, ставится, когда
  игра хоста создала лобби). Игра хоста — прямо в хаб (`ws://localhost:8787/coop`).
- **Игрок**: вход в лобби Steam (по id или `GameLobbyJoinRequested`), хост — владелец лобби. Каждое WebSocket-соединение
  игры с мостом (`ws://localhost:8787/coop`) — соединение туннеля к хосту; у хоста оно — соединение хаба.
- **Туннель** — P2P Steam (`SteamNetworking`, надёжные пакеты; NAT обходят ретрансляторы Steam — порты не нужны).
  Кадр: тип (открыть / данные / закрыть / пинг), номер соединения, часть / частей; сообщения больше 256 КБ режутся
  (пакет Steam — до 1 МБ, проект — ~2.6 МБ). P2P хост принимает только от участников своего лобби Steam, игрок — только
  от хоста. Вышел из лобби / молчит 30 с — соединения игрока закрываются.
- Игре мост сообщает о себе: `GET /steam` (CORS) — роль, лобби Steam, участники, код игрового лобби; модалка опрашивает
  `localhost:8787` (и адрес из поля «Сервер» — мост с `--port`) раз в 3 с, пока она открыта (моста нет — в консоли
  браузера `ERR_CONNECTION_REFUSED` на каждый опрос, это ожидаемо). Мост отдаёт и собранную игру на `/`.
- Мост слушает только `127.0.0.1` (`--lan` — и сеть).

### 4.3. Проверка

- Без Steam: `tools/steam-bridge.test.mjs` — хост + 3 игрока через туннель на тестовой сети, проект кусками, пятому —
  отказ, уход и обрыв; `node tools/qa-coop-steam.mjs` — то же в браузере по кнопкам Steam.
- Со Steam: нужны два компьютера (или два аккаунта Steam) — P2P с самим собой Steam не даёт. Хост:
  `npm run steam -- host` → id лобби; игрок: `npm run steam -- join <id>`; дальше — кнопки в модалке.

## 5. Ограничения и дальше

- Сервер не проверяет операции (доверие между друзьями) и держит лобби в памяти: перезапуск отдельного сервера —
  лобби пропадут (клиенты увидят «Лобби не найдено»).
- Сцены спец-локаций не общие: в лифте/на лестнице каждый сам по себе (мир за ними — общий).
- Находки, инвентарь, опасность (`src/game/`) в коопе пока не синхронизируются.

QA в браузере (`node tools/qa-coop.mjs`) поднимает свой vite без слежения за файлами: в дереве параллельно работают
другие сессии, и HMR их правок перемонтировал бы страницы посреди прогона.
