# Игровой цикл прогулки: находки, опасность, карточка тира, сохранение

Логика игры **без движка**: где лежит лут, что происходит при заходе в комнату, что игрок видит в карточке
комнаты и в инвентаре, как это сохраняется. Работает поверх того же JSON прогона (`RunExport`, docs/GENERATOR.md
§6), что получает болванка и Babylon, — в евклидовом прогоне, складчатом (4D) и в бесконечном мире «Прогулки».

| что | где |
|---|---|
| типы: находка, событие, состояние игры | `src/game/types.ts` |
| цикл: находки, заход, подбор, сохранение | `src/game/state.ts` |
| размещение находок (пол / мебель / споты) | `src/game/place.ts` |
| тексты для игрока: карточка тира, инвентарь, опасность | `src/game/rules.ts` |
| тесты | `src/game/*.test.ts` (прогоны пресетов: обычный, 4D, бесконечный мир) |
| проходимость (капсула игрока) | `src/gen/walk.ts`, docs/GENERATOR.md §8 |
| розыгрыш тира и лута комнаты | `src/gen/generate.ts` `rollContent`, docs/GENERATOR.md §5 |

Зависимости `src/game/`: `src/gen/walk.ts` (проходимость), `src/gen/rules.ts` (тексты правил тира),
`src/blockout/core.ts` (`propHeightM` — высота мебели), `src/model/rng.ts`. React и Babylon не нужны.

## 1. Цикл прогулки (для Влада)

```ts
import { enterRoom, newGame, pickupsLeft, readGame, takePickup, writeGame } from './game/state';
import { dangerText, inventoryView, tierCardInfo } from './game/rules';

const game = readGame(worldKey);            // сохранение мира или новая игра (ключ — gameKey(worldKey))

// игрок перешёл порог → комната instId
for (const ev of enterRoom(game, rx, instId, dangerLimit)) {
  if (ev.type === 'enter' && ev.first) showCard(tierCardInfo(rx, ev.tierId), ev.dangerAdd);
  if (ev.type === 'danger-limit') levelIsBurning();   // один раз за игру
}

// показать находки комнаты (и соседей, которые видно через порталы)
for (const p of pickupsLeft(game, rx, inst)) spawnPickupMesh(p);  // p.x, p.y — клетки плана, p.z — метры

// игрок взял находку
takePickup(game, p);                         // событие 'pickup'; повторно не берётся
writeGame(game);                             // в localStorage; удобно — с задержкой, как мир
hud(inventoryView(rx, game), dangerText(game, dangerLimit));
```

- **Координаты находки** — как у всего `RunExport`: план в клетках (`x` вправо, `y` вниз), метры = клетки ·
  `cellM`. В Babylon (docs/BLOCKOUT.md): `X = x·cellM`, `Z = −y·cellM`, `Y = z` (высота над полом, метры). Слой
  W и этаж — у экземпляра (`inst.w`, `inst.floor`), находка принадлежит экземпляру `p.inst`.
- **`pickupsOf(run, inst)`** — все находки экземпляра, включая подобранные; `pickupsLeft` — без них. Результат
  кэшируется по объекту экземпляра (~1.5 мс на комнату при первом вызове, дальше — копия из кэша).
- **`dangerLimit`** — порог «уровень горит» (`economy.dangerLimit`). Полный экспорт (`exportRunJSON`) кладёт его в
  корень — `dangerLimitOf(rx)`; в «Прогулке» его можно взять прямо из проекта.
- Состояние игры (`GameState`) — простой объект; функции его меняют на месте и возвращают события.

## 2. Где лежат находки и почему

Находки комнаты разыграны генератором при её создании (`instances[].spots[].content`, `instances[].loot`) — игра
их только раскладывает. Раскладка **детерминирована**: тот же мир — те же места, после перезагрузки тоже.

| откуда | где лежит | `from` | id |
|---|---|---|---|
| спот с предметом (вариант группы спотов) | в точке спота; если спот попал на мебель — на ней/в ней | `spot` | `${inst}:spot:${spotId}` |
| строка тира с `where` («сервант», «бутылки», «шкаф-инструменты») | в этой мебели (`decorId`) | `tier` | `${inst}:loot:${i}` |
| лут комнаты, строки тира без `where` | на полу | `room` / `tier` | `${inst}:loot:${i}` |

`i` — номер в `inst.loot`. Готовый предмет из магазина (строка тира «из Ларька») несёт `shopId`.

### 2.1. В мебели

Точка — центр мебели на плане; несколько находок в одной мебели — вдоль её ширины (на 70 % ширины), не в одной
точке. **Высота** — по высоте болванки мебели (`propHeightM`, та же, что у болванки в 3D):

- мебель от **1.2 м** (сервант 1.8, шкаф 1.9, стенка 2.0, холодильник 1.5) — находка **внутри**, на середине
  высоты: на полке серванта, в шкафу (`z` = 0.9 у серванта);
- ниже (стол 0.75, тумба 0.85, ящик с бутылками 0.35) — **сверху**.

Это же правило — для предмета на споте, если спот стоит в контуре мебели (предмет на столе — `z` = 0.75).

### 2.2. На полу

Цель: лут лежит там, куда игрок может подойти, но **не в проходе** — не в дверях и не на пути между дверями, — и
не кучей в одной точке. Всё считается по сетке проходимости `src/gen/walk.ts` (капсула игрока радиусом 0.3 м,
мебель и prop на спотах — препятствия, ковры — нет).

Клетки пола комнаты делятся на классы (`floorPlan(run, inst).cls`, `Slot`):

| класс | что это |
|---|---|
| **у стены** (`Wall`) | центр капсулы может встать и дойти до дверей, а в 0.2 м дальше уже не может — стена или мебель не дальше ~0.5 м |
| **свободно** (`Free`) | центр капсулы встаёт, вокруг просторно |
| **рукой достать** (`Reach`) | капсула сюда не встаёт (у стены, за тумбой), но место, куда встаёт, — не дальше **0.6 м** по полу; до стены и мебели ≥ 0.15 м (предмет не «влипает» в геометрию) |
| **у проёма** (`Door`) | ближе **0.6 м** к линии любой двери/метки |
| **на пути** (`Path`) | ближе **0.5 м** к пути центра капсулы между двумя проёмами |

**Путь между проёмами** — так, как ходит игрок: от середины одной двери к середине другой по кратчайшему
маршруту в обход мебели, «натянутый» в ломаную (в пустой комнате — прямая). Считается для каждой пары проёмов
комнаты, связанных и тупиковых одинаково (раскладка не меняется, когда мир дорастает за дверью). Капсула
занимает ±0.3 м от пути — находка в 0.5 м лежит в 0.2 м от плеча идущего, но не под ногами.

**Выбор точки** для каждой находки на полу по очереди (`SPREAD_M` = 0.7 м):

1. случайная клетка «у стены», не ближе 0.7 м к уже положенным находкам (на полу, включая предметы на спотах);
   нет — «свободно»; нет — «рукой достать»;
2. то же с разносом 0.35 м;
3. тесная комната (всё место — у дверей или на пути): клетки «у проёма»/«на пути», не ближе 0.35 м к положенным, —
   из лучшей четверти по тому, насколько они залезли в зону (подальше и от двери, и от пути);
4. иначе — клетка, самая удалённая от уже положенных.

Случайность — от **места экземпляра** (комната, поворот, сдвиг, слой W, этаж) и номера находки, а не от id
экземпляра: в бесконечном мире id зависят от порядка обхода, а место и наполнение — нет, поэтому комната по тому
же адресу получает те же находки на тех же местах при любом маршруте игрока (тест).

### 2.3. Цифры на пресетах

5 прогонов (3 обычных по 40 комнат, складчатый на 87, бесконечный мир на 64 комнаты) — 280 комнат, 316 находок:

- **1.1 находки на комнату** (в среднем), **71 %** комнат с находками, до 5 в одной;
- **86 % — на полу**, 13 % — предметы на спотах, ~1 % — в мебели (строки тира с `where` редкие: самогонка в
  серванте 5–30 %);
- на полу: **45 % — у стены**, **25 % — «рукой достать»**, **30 % — в зоне двери или пути**. Последние — только
  тесные комнаты: санузлы, туалеты, кладовки, прихожие на 4–7 дверей, где вся площадь, куда встаёт капсула, —
  в 0.6 м от двери (в совмещённом санузле 1-335 капсула встаёт ровно в одной клетке). Там находка лежит в самом
  дальнем от двери и пути углу;
- находки на полу одной комнаты — не ближе 0.35 м друг к другу (обычно ≥ 0.7 м); в одной точке — никогда;
- время: ~1.5 мс на комнату при первом вызове (две сетки проходимости + пути), до ~15 мс на больших холлах.

## 3. Опасность и порог

- **Первый заход** в комнату: опасность игры `+= instance.danger` (прирост тира — «Проход: опасность +N»),
  комната запоминается (`visited`). **Повторный заход** опасность не добавляет. Событие `enter` — всегда
  (`first`, `dangerAdd`, итог `danger`).
- **Порог**: как только опасность **стала больше** `dangerLimit` (как в редакторе: «уровень горит, когда
  опасность больше»; ровно на пороге — ещё нет), — событие `danger-limit`, **один раз за игру** (`overLimit`).
  `dangerLimit` = 0 — порога нет.
- В прогулке опасность — **сумма по всем посещённым комнатам**, а не по пути от старта (`dangerAcc` генератора
  считает путь по дереву роста — для карты, не для игры). Вернулся назад — опасность не убывает.
- `minFloor` — самый нижний этаж, где был игрок (спуск через «Бесконечную лестницу», docs/LOCATIONS.md).

Правило игроку — одной фразой: **«Каждая новая комната добавляет опасность своей элитности. Больше N — уровень
горит.»** `dangerText(game, limit)` → «Опасность 34 из 100», «Опасность 112 из 100 — уровень горит».

## 4. Карточка тира

При первом заходе HUD показывает элитность комнаты и её правило — **тем же текстом, что видит геймдизайнер во
вкладке «Экономика»** (`tierRuleLines`, `src/gen/rules.ts`). `tierCard(rx, tierId)` — строки, `tierCardInfo` —
то же с цветом, уровнем, приростом опасности и заметкой:

```
Элитность 1 — Обычная квартира
Проход: опасность +2
Копейки: до 6 — 50%, иначе до 4 — 70% (в среднем 2.6)
Самогонка в «сервант»: 5%
```

Без тира — «Обычная комната / Проход: опасность не растёт». Правило ступеней («до 6 — 50%, иначе до 4 — 70%»)
понятно игроку как есть: сначала бросок на большую горсть, не вышло — на меньшую (docs/GENERATOR.md §5.4).

**Нужны полные таблицы**: `exportRunJSON` кладёт тиры целиком (с `loot`) и `shops`. Если экспорт урезан (тиры
только `id/name/level/color/danger`, без магазинов) — карточка покажет заголовок и опасность, без лута.

## 5. Инвентарь

`inventoryView(rx | items, game)` — строки для HUD: **сначала валюты** (тег `currency`: копейки, электронные
компоненты, самогонка — в порядке таблицы предметов), **потом товары**; имя и цвет — из таблицы предметов;
неизвестные предметы — в конце (имя = id); нули не показываются.

## 6. Сохранение

- `saveGame(game)` → JSON (`format: 'room-forge-game'`, `version: 1`, `worldKey`, инвентарь, подобранные id,
  посещённые комнаты, опасность, порог, этаж). `loadGame(json, worldKey)` — битый JSON, чужой формат/версия или
  **другой мир** → `null`; мусор в полях отбрасывается поштучно.
- Ключ в localStorage — `gameKey(worldKey)` = `room-forge/game/${worldKey}`, рядом с сохранением мира
  (`worldKey(seed, mods)`). `readGame` / `writeGame` — с защитой от отсутствия/переполнения хранилища.
- Подобранное и посещённое хранится по **id экземпляров**. Они стабильны, пока жив сохранённый мир. Если мир
  начат заново (`world.stale` — проект изменился, сохранение мира не подошло), игру тоже надо начать заново
  (`newGame`) — иначе id укажут на другие комнаты.

## 7. Ограничения

- Находки — точки, без размеров: движок сам решает, как их рисовать и с какого расстояния брать (рекомендуется
  ≥ 0.9 м от центра капсулы: «рукой достать» гарантирует ≤ 0.6 м до места, куда встаёт центр).
- «Внутри мебели» — точка на середине высоты по центру плана; дверцы, полки и анимация открывания — дело движка.
- Предмет на споте лежит ровно в точке спота: если автор комнаты поставил спот предмета в стену или в проход,
  так и будет (споты — решение автора).
- В тесных комнатах (санузел, туалет, кладовка, прихожая-«звезда») находка может оказаться у двери или на пути —
  места вне зон там просто нет (§2.3).
- Текст «в «сервант»» — тег мебели как есть, без склонения (то же в редакторе).
- `pickupsOf` кэширует по объекту экземпляра: если экземпляр мутировать на месте (сдвинуть мебель), кэш не
  узнает — создавайте новый объект (как делает «Прогулка» при изменении связей).

## 8. Что дальше

- **Существа: Заяц и Шершун.** Электронные компоненты — приманка: бросок компонента отвлекает существо на
  несколько секунд, компонент тратится (`inventory[it_components] −= 1`, событие `throw`). Нужно: точка падения
  (те же клетки «у стены/свободно» из `floorPlan` — где существо может «найти» приманку), время отвлечения в
  правилах тира или существа, понятная игроку строка («Компонент отвлекает Зайца на 5 с»).
- **Опасность → существа.** Опасность уже копится по комнатам; дальше — что именно «горит»: чаще появляются
  существа, самосбор, гаснет свет. Порог `dangerLimit` и событие `danger-limit` — точка подключения.
- **Проходки за самогонку.** Барыга продаёт «Проходку на элитный этаж» (`economy.passes`): в генераторе она уже
  умножает веса тиров ≥ 2 и шансы предметов. Для прогулки нужно: покупка (`inventory[it_samogon] −= price`),
  активная проходка в состоянии игры и ГСЧ комнат, раскрытых после покупки (модификатор сида или параметр
  раскрытия), — правило «с проходкой элитные квартиры втрое чаще» понятно игроку.
- **Магазины.** Трата валют по веткам (`economy.shops`: Ларёк — копейки, Электрик — компоненты, Барыга —
  самогонка): `buy(game, shopId, offerId)` поверх того же инвентаря.
- **Детекторы 4D** (товар Электрика): данные есть — слой `inst.w`, соседи по 3D в других слоях
  (docs/GENERATOR-4D.md §10). Детектор может показывать «здесь же, в слое +1, — кухня с лутом» (находки соседа
  по слою — тот же `pickupsOf`), тратить батарейки.
- **Модификаторы сида** (docs/GENERATOR-4D.md §15.9): «+подвал», «лабиринт», «тьма» — и для игры: «скупой мир»
  (множитель лута), «горячий» (меньше `dangerLimit`). Ключ мира их уже различает — сохранения игры тоже.
